## 部署方式选择

**二进制 + systemd 用户服务**，不用 Docker。理由：

1. 用户已装好二进制（`/home/ubuntu/.local/bin/magpie`，v0.1.1292 = 当日 release）
2. 服务器已有 nginx + CF 域名体系，反代比 Docker 端口映射更顺
3. 二进制可自动发现服务器上已装 agent（实测识别：OpenCode / Hermes Agent / Muse Code / ZCode）
4. Docker 版对容器外调用强制 gateway key，且 sign-in 回调经 `localhost` 在容器内不可用，配置更绕

Docker 适用场景：NAS、多机共享且不想污染宿主机。本机不适用。

## 安装步骤（实际执行）

```sh
# 已由用户完成：下载到 ~/.local/bin/magpie（v0.1.1292）
export PATH=$PATH:/home/ubuntu/.local/bin
WEBKEY=$(head -c 24 /dev/urandom | od -An -tx1 | tr -d ' \n')
MAGPIE_WEB_KEY=$WEBKEY MAGPIE_ADDR=0.0.0.0:3425 magpie daemon install --web --lan
```

生成 `~/.config/systemd/user/magpie.service`，linger 已开启（开机自启）。

## 实测证据（2026-10-19）

| 测试 | 结果 |
|---|---|
| `magpie daemon status` | active (running)，gateway answers |
| 本机 `127.0.0.1:3425/v1/models` | 200 |
| 公网 `https://magpie.sunfolower.cn/v1/models`（带 key） | **200** `{"data":[],...}` |

| 旧入口 `magpie.autofile.cc.cd` | 已删除（DNS + 专用隧道），解析不再命中 |

> `/v1/models` 当前为空是**预期**：还没加 provider。
