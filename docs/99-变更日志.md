> 结论：`DEC-MAG-022` 判定的「网页接口走不通」**只对了一半**。积分确实不能用于 `/api/llm_proxy/v1`

> `127.0.0.1:8399` 完全同构，**现有 Genspark 插件一行未改**。

## 2026-11-16 · MonkeyCode 微信扫码登录四连修复 + uuid 错位根治 <!-- DEC-MAG-019 -->

> 结论：用户报告「扫码成功但服务器没反应」，五轮排查后定位为**结构性 uuid 错位** + 三个连带 bug，全部修复并实测闭环（用户最终自助扫码登录成功，新账号槽 `#7c6js2` 当日 claimed +100）。

- **根因（结构性）**：qrconnect 授权页**每次加载生成新 uuid**。旧实现把 authUrl 交给 magpie UI 打开 ⇒ 用户浏览器重新加载页面生成 uuid-B 并显示其二维码，插件轮询的却是 startWechatLogin 的 uuid-A ⇒ 用户侧「扫描成功」、服务器侧永远 408。**修复**：authorize 返回的 `url` 改为**二维码图片直链** `login.qrUrl`（`open.weixin.qq.com/connect/qrcode/<uuid>`，与轮询同一 uuid）。
- **连带修复**（都是旧服务器侧改动留的雷，逐个被用户实跑引爆）：
  ① `lp.baizhi.cloud` 不在 CLB 证书 SAN ⇒ Node fetch `ERR_TLS_CERT_ALTNAME_INVALID`，扫码后轮询全挂（`wechat-login.mjs` 加 `lpRelaxedFetch`）；
  ② `bridgeLogin` 未导入（`bridgeLogin is not defined`）；
  ③ `accountCookieFile(env)` 传对象给 `dirname()` 抛 `The "path" property must be of type string`（改 `cookiePaths(env)` 定位 + 原子写；`writeAccountCookie` 悬空引用一并清除）。
- **验证纪律（教训）**：前两轮「改完即部署」连炸两个运行时错误（都是用户截图暴露），第三轮起**服务器端到端实跑**（bridge→status→mint→文件定位）后才交付 ⇒ 立即闭环。**部署插件必须 `node --check` + 真链路冒烟，缺一不可。**
- **对照实锤**：修复后日志序列 `已扫码，等待手机确认…` 出现三次 ⇒ uuid 对齐，用户动作能到服务器了。
- **连带修复 ④（多账号 A 通道隔离）**：用户扫第二个微信登录后，第一个号（橘生淮南）的百智 A 通道签到丢失——根因是 `baizhi-cookies.json` 全局单槽只存最后登录者。修复：新增 `bzFor(auth, env)`（优先槽内 `metadata.bz_cookie`，回退全局兼容），`makeUsage`/`makeCheckin` 两处调用点切换；主槽手工迁移橘生淮南 bz_cookie。重启后两槽 quota 各自正确（橘生淮南 100 积分 / 齊名好難 600 积分）。
- **上游行为备忘（2026-11-16 实锤）**：MonkeyCode 同账号**重铸 key 会吊销旧 key**——同账号再登录/再铸 key 后，其它指向该账号的槽会 403「已退出登录」。处理：界面「重新登录」或移除多余槽，活会话重铸即恢复。避免触发：每个微信号只保留一个槽。
- **终态（2026-11-16 复核）**：两微信号（橘生淮南 019d9669-… / 齊名好難 #7c6js2）推理、签到、余额展示全部实测通过（指定槽 PONG 200；当日 claimed +100 显示正常）；`baizhi_session` 重抓闭环（本机 --add + scp + 服务器触发签到 already）。会话有效期：monkeycode 槽至 11-21/22，百智至 ~12-15，到期自动续期（失败则界面「需要重新登录」→ 重新扫码即恢复）。
- 附带产物：`plugins/monkeycode-server-snapshot/`（服务器版插件快照入库，含 11-09 未回填改动）；服务器备份 `/tmp/index.mjs.bak*`、`/tmp/wechat-login.mjs.bak-1115`。

## 2026-11-08 · 修 Codex 502：mihomo 加回环直连规则 <!-- DEC-MAG-016 -->

> 结论：服务器上的 Codex 带 `HTTP_PROXY=172.17.0.1:17900` 且 `base_url=http://127.0.0.1:3425/v1`，
