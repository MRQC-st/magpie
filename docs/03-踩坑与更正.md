## 1. 域名选错：用了 autofile.cc.cd

**现象**：按知识库 `cloudflare` 项目（CF2 账号）的隧道 runbook，创建了 `magpie-tunnel` 并把
`magpie.autofile.cc.cd` 指到它。用户纠正：应使用 **`sunfolower.cn`**。

**根因**：知识库同时存在两套 CF 资产：
- CF2 账号：`autofile.cc.cd`（免费域名，命名隧道体系）
- 主账号：`sunfolower.cn`（自有域名，服务器 nginx 反代体系）

**教训**：选域名前先问清「哪个域名」，不要从"最近用过的 runbook"推断。
两套账号权限不同（CF2 有 Tunnel 权限，主账号有 zone DNS 权限），
跨账号的隧道 CNAME 也不能假设可用。

**已处置**：删除 `magpie.autofile.cc.cd` DNS 记录 + `magpie-tunnel` 隧道 + 专用 cloudflared 服务。

## 2. CF API 的 JSON 在 SSH/curl 中被吞

**现象**：`curl -d '{"name":"magpie-tunnel"...}'` 经 SSH 传到服务器后，CF 报
`Invalid symbol 45 (dash), offset …`。

**根因**：多层 shell 引号嵌套（本地 PowerShell/Bash → SSH → 远端 shell → curl）。
`--data` 里的 JSON 被拆坏。

**教训**：
- 复杂/含引号的 JSON 一律**先落文件**（`--data @file`）或改用 Python 脚本；
- 参数不要层层转义，优先 `cat 本地文件 | ssh host "cat > /tmp/f"` 传输；
- 凭据不放进命令行参数，改为 stdin 传给远端进程（`scripts/cf-domain.py` 就是这么做的）。

## 3. 「HTTP 400 账号标识无效」实际是变量没传过去

**现象**：从本地 curl 到 CF 返回 000，从服务器 curl 返回 400 `Invalid format for Authorization header`。

**根因**：本地没有 source `.env`，`$CF_TOKEN` 展开为空；同时本地对该域名的直连/代理都不可达（HTTP 000）。
**服务器到 CF API 是通的**。

**教训**：报错要分层读——400 说明请求到了 CF，只是 header 格式不对；000 说明根本没连上。
先用服务器（已知可出网）做对照，再判断"是网络问题还是参数问题"。

## 4. nginx：站点放 sites-enabled 且在 default_server 之后

**现象**：`/etc/nginx/sites-enabled/magpie.sunfolower.cn` 生效后，请求仍落到
`sites-enabled/sunfolower.conf`（`default_server`）→ `127.0.0.1:3000`（未运行）→ **502**。

**根因**：`nginx.conf` 按 `include` 的**文件顺序**匹配 server。
`sites-enabled/sunfolower.conf` 含 `listen 80 default_server; server_name _;`，
且它的文件名（`s`）排在 `magpie`（`m`）之前… 实际上 `m` < `s`，真正的问题是
`default_server` 的 server 在**同一端口**上抢了未被精确匹配的请求；
而首版请求的 `Host` 是 `magpie.sunfolower.cn`，本应命中本 server——
**实际原因是首版放在 `sites-enabled` 下且 nginx 未 reload 到正确顺序**（见首轮 502）。
无论根因细节，**把它放进 `conf.d/`（先加载）后稳定命中**。

**教训**：
- 新增 server block 时，先 `curl -H "Host: <域名>" http://127.0.0.1/` 验证命中哪个 server；
- 与已有 `default_server` 共存时，新站点放 `conf.d/` 或确保精确 server_name 先加载；
- **不要**靠重命名（`00-` 前缀）污染共享 `sites-enabled` 目录。

## 5. 代理/本地网络导致 000 不等于服务坏

**现象**：本地 Windows `curl https://magpie.autofile.cc.cd`（当时错误域名）返回 000 或 502，
但服务器自身测试通过。

**根因**：本地环境挂有 Clash（`127.0.0.1:7890`），schannel 对部分 CF 回源 TLS 失败；
且当时 DNS/证书链尚未就绪。
**真正验证**应以**服务器侧**对 `https://magpie.sunfolower.cn` 的请求为准（已 200）。

## 6. 服务文件里含凭据，别整文件外传

`~/.config/systemd/user/magpie.service` 含 `MAGPIE_WEB_KEY`。
任何"把服务文件发出来看看"的操作都会泄露 key。
需要排查时只读 `ExecStart` / `Environment=` 的非敏感行（如 `MAGPIE_ADDR`）。
