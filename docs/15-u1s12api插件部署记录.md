# 15 · u1s12api 插件部署记录（2026-10-30）

> **本文是什么**：把 `u1s12api`（u1s1 账号接入 magpie 的 provider 插件）装到 magpie 网关服务器上的实施与验证记录（SSOT）。
> **本文不负责**：magpie 网关部署（→ `00`/`01`）、第三方社区插件接入（→ `14`）、LobsterAI 插件迁移（→ `10`/`11`/`12`）、zcode 账号导入（→ `13`）。

## 一、这是什么

| 项 | 值 |
|---|---|
| 来源 | 用户自带的 zip（微信文件 `2026-10/u1s12api.zip`），不是社区 spec |
| 包 | `u1s12api` 0.2.0，MIT |
| 安装形态 | **本机文件夹插件**（spec 即路径），与 `plugins/lobster` 同款：`/home/ubuntu/magpie-plugins/u1s12api` |
| provider | `u1s12api`（模型 `deepseek-flash` / `qwen3.8-flash` / `glm-5.3-flash`） |
| 站点 | `u1s1app.com`（CN）/ `u1s1.dev`（Intl），API 基址 `api.u1s1app.com/v1` |

关键机制（决定部署形态的一条）：

- **模型调用不是插件自己发 HTTP，而是 spawn 本机 u1s1 CLI**（`node <cli dist>/index.js -p <prompt>`）。
  CLI 自己签名（DPoP + attestation + `x-u1s1-*` 头），网关看到的就是官方客户端 ——
  免费额度（登录打卡包）只认官方客户端，纯 HTTP 复刻会被 `client_integrity_review` 拒。
  ⇒ **magpie 所在的机器上必须装 u1s1 CLI**，否则登录/用量/打卡还能用，模型调用一律拒。
- **登录**：设备流 `/auth/device/start` → 浏览器批准 → `/auth/device/poll`，
  凭证写 `~/.u1s1/config.json`（与官方 CLI 共用同一个文件）。
- **用量**：读 `/v1/me`，按网站仪表盘口径展示（用量包分组、最早到期、现金余额）。
- **打卡**：走**网站**会话（`~/.u1s1/web-session.json` 里的 `u1s1_session`），
  POST `u1s1app.com/api/packages/login-checkin/claim`；插件按站点自身行为发 null 验证码 token（fail-open）。

## 二、装之前的代码审阅结论

读了 `index.mjs`（1016 行）全文 + `login-once.mjs` / `extract-cookie.mjs` / `probe-claim*.mjs` / `smoke.mjs`：

- **网络出口只有三处**：`api.u1s1app.com`、`u1s1app.com`、`127.0.0.1:9222`（浏览器 CDP）。
  没有第三方回传、没有遥测外发。
- **cookie 只写本地文件**（`~/.u1s1/web-session.json`，0600），不外发。
- `probe-claim*.mjs` / `smoke.mjs` / `recon-app.js`（0 字节）是开发期探针，服务器上不会自动运行；
  原样保留是为了服务器上的目录与用户的 zip **逐字节一致**（见 §三.2 的 sha256 核对）。

## 三、服务器部署（已完成）

### 3.1 装 u1s1 CLI

```sh
npm i -g u1s1-cli        # → 1.14.5
```

- npm 全局前缀 `/home/ubuntu/.npm-global` ⇒ CLI 落在
  `/home/ubuntu/.npm-global/lib/node_modules/u1s1-cli/dist`（`index.js` 在里面）。
- CLI 要求 `node >= 22.19.0`；服务器 `/usr/bin/node` 是 v22.22.2，另有 nvm 的 v24.15.0，都满足。
  `node <dist>/index.js --version` → `u1s1 v1.14.5`。

### 3.3 让插件能找到 CLI（Linux 上的必需一步）

插件的 `findCliDist()` 只列了 Windows 候选路径（Scoop / `Program Files` / `APPDATA\npm`…），
Linux 上一个都不命中 ⇒ 必须显式给 `U1S1_CLI_DIST`。
用 systemd drop-in（不动 `magpie daemon install` 写的主 unit，重装也不会丢）：

```ini
# ~/.config/systemd/user/magpie.service.d/u1s1-cli.conf
[Service]
Environment="U1S1_CLI_DIST=/home/ubuntu/.npm-global/lib/node_modules/u1s1-cli/dist"
```

`systemctl --user daemon-reload && systemctl --user restart magpie` 后，
已确认 **plugin-host 子进程**（`magpie-bun run …/plugin-host/host-*.js`）继承了
`U1S1_CLI_DIST` 与含 `/usr/bin` 的 PATH ⇒ 插件 spawn 到的 `node` 是 v22.22.2。

### 3.4 注册与连通性

```sh
magpie plugin add /home/ubuntu/magpie-plugins/u1s12api
# → ✓ added /home/ubuntu/magpie-plugins/u1s12api
magpie plugin list | grep -A2 u1s12api
# → /home/ubuntu/magpie-plugins/u1s12api  on
```

连通性（服务器出网）：`api.u1s1app.com/v1/models` → **401**（缺凭据，符合预期）、
`u1s1app.com` → 200。

> 判据仍是 `magpie plugin list`。

## 四、还差用户侧的事

1. **登录（用户自理）**：

   ```sh
   export PATH=$PATH:/home/ubuntu/.local/bin
   magpie plugin login u1s12api 1     # 方法 1 = 浏览器授权（设备流）
   ```

   命令会打印 u1s1 的 `verify_url`；在自己浏览器里批准即可 ——
   设备凭证会落在**服务器**的 `~/.u1s1/config.json`，magpie 侧记一条 oauth。
   （方法 2「复用本机 CLI 登录态」要求 `~/.u1s1/config.json` 已存在，本机没装 u1s1 CLI，用不了。）

2. **每日打卡（可选，但要用上「登录打卡包」就需要）**：
   本机 Chrome 登录 u1s1app.com 后，用带调试端口的浏览器 + 插件目录里的 `login-once.mjs`
   生成 `~/.u1s1/web-session.json`，再由本机脚本搬到服务器：

   ```powershell
   powershell -ExecutionPolicy Bypass -File scripts/import-u1s1-web-session.ps1
   ```

   服务器上没有浏览器 ⇒ 插件自带的 CDP 兜底（`127.0.0.1:9222`）在服务器上永远拿不到会话，
   只能走这条路。
   打卡开关在 magpie 设置里：`settings.json` 的 `pluginCheckins.u1s12api=true`。

## 五、注意事项

1. **每次请求 spawn 一个 CLI 进程**：走的是 CLI 的 `-p` 一次性脚本模式（CLI 没有 `--mode rpc`），
   所以没有流式增量、也没有 token 计量，插件自己把整段 stdout 当答案。
   `package.json` 里 `maxConcurrency: 2` —— 插件自认并发上限是 2。
2. **打卡 cookie 可能绑 IP**：本机生成、服务器使用，跨 IP 可能被判失效；
   失效时插件会删掉服务器上那份 `web-session.json` 并提示去网站手动领。
3. **免费额度只认官方客户端**：这正是插件必须 spawn CLI 的原因；
   纯 HTTP 复刻会被 `client_integrity_review` 拒。想要不受客户端限制就得升级付费包（付费余额无此限制）。
4. **验证码 fail-open 是站点自身行为**：插件照站点页面那样发 null 验证码 token，服务端接受。
   若站点改判策略，打卡会退化成「去网站手动领」（插件会报 `inactive` 并给出提示）。
5. **版本要求**：CLI ≥ 1.11.2（当前装的是 1.14.5），插件 README 提到的最新是 1.14.4。

## 六、回滚

- 卸插件：`magpie plugin rm /home/ubuntu/magpie-plugins/u1s12api`。
- 清账号：删服务器上的 `~/.u1s1/` 与 `~/.config/magpie/plugin-auth.json` 里的 `u1s12api` 条目，
  再 `magpie daemon restart`。
- 卸 CLI：`npm uninstall -g u1s1-cli`，并删掉 systemd drop-in 后 `daemon-reload` + 重启。
