## 一句话

magpie 是**模型网关**：所有 agent（本机 Claude Code / 服务器上的 OpenCode、Hermes 等 / 其他设备）
通过同一个网关走 provider，网页只用于管理。二进制部署在腾讯云，systemd 用户服务常驻。

- 服务器：腾讯云 `ubuntu@43.131.227.120`（Ubuntu 22.04，systemd **用户**服务）
- magpie 版本：**0.1.3105**（2026-11-06 实测；插件协议 = OpenCode v1）
- 公网入口：`https://magpie.sunfolower.cn`（网关 `/v1/`、`/v1beta/`；网页 `/`）
- 本机回环：网关 `127.0.0.1:3425`、网页 `127.0.0.1:3430`

## 架构

| 层 | 组件 | 位置 / 端口 |
|---|---|---|
| 入口 | 浏览器 / agent | HTTPS → `magpie.sunfolower.cn` |
| 边缘 | Cloudflare（托管 TLS、橙云代理） | 回源 HTTP:80 |
| 反代 | nginx 站点 | `/etc/nginx/conf.d/magpie.sunfolower.cn.conf`（不是 sites-enabled，原因见 `02`） |
| 网关 | magpie gateway | `127.0.0.1:3425`（`MAGPIE_ADDR=0.0.0.0:3425`） |
| 网页 | magpie web | `127.0.0.1:3430`（`magpie serve --web=0.0.0.0:3430`） |
| 插件 | folder plugin 就地加载 | `/home/ubuntu/magpie-plugins/<name>`，与宿主同进程 |
| 服务单元 | `~/.config/systemd/user/magpie.service` | `magpie daemon restart` 生效 |

nginx 的两条转发规则：`/v1/`、`/v1beta/` → `3425`；其余 → `3430`。

## 常用命令（服务器上）

```sh
export PATH=$PATH:/home/ubuntu/.local/bin      # 非交互 SSH 的 PATH 里没有 magpie
magpie daemon status                          # 服务状态 + 网页链接
magpie daemon restart                         # 改完插件后重启生效
magpie plugin list                            # 已装插件 + provider + 登录态（判据在这条）
magpie plugin add <path>                      # 装一个 folder plugin（就地加载）
magpie plugin login <provider> <n>            # <n> = 第 n 个登录方式（1-based）
magpie plugin logout <provider>
magpie provider test <provider>               # 冒烟：真发一次请求（只看向状态码，须复核正文）
magpie models | grep <provider>
magpie quota <provider>
magpie gateway-key list                       # 网关 key 列表
magpie gateway-key add "文件名"               # 新增设备 key（明文只显示一次）
journalctl --user -u magpie -f                # 日志（插件日志带 plugin: 前缀）
```

## 文档治理约定

**分级：L1+（编号文档为骨干）。** 判级问两句：会不会长期迭代？会不会产生可复用经验？
magpie 两问都是「会」，但**可复用经验已按主题沉淀进编号文档**（每主题一份 SSOT），
不存在「日志堆积、翻目录找答案」的问题 ⇒ L2 的 `field-journal/` + `topics/` 分层**没有对象**，
硬建就是平行体系（违反硬规则五）。升级触发条件：① 出现同一事实两处维护；
② 需要按场景跨主题检索经验；③ `99` 触发归档线（>800 行或 >半年）。届时按兄弟项目
`model-reverse` 的 `field-journal/` + `topics/` + lint 门禁照搬。

**五条硬规则**（摘要，全文见 skill 的 `references/project-docs-spec.md` §3）：

1. 每份编号文档开头三行内写「本文是什么」+「本文不负责」。
2. `00` 必须有文档地图 + 分工表，覆盖每一份编号文档，判据是「一个事实只在一处维护」。
3. 跨文档引用用稳定 ID（文件名 / `DEC-*`），**不写 `文件:行号`**。
4. 台账（`99`）= 单文件 + append-only + 带覆盖标记的索引 + 校验脚本。
5. `docs/` 下的子目录要过六条判据（≥4 条 = 正当结构，<3 条 = 违规平行体系 ⇒ 合并）。

**其它约定**：

- `99` 每条 = 日期 + 一行结论 + `DEC-*` 编号；正文进主题文档（`99` 只做证据时间线）。
- `AGENTS.md` = 活总入口（状态结论层）；`00` = 全量结构层；`99` = 证据时间线层。
  **「当前状态」只写一份**，写在 `AGENTS.md`；其它文档引用它，不复制。
- 凭据纪律：口令只放服务器 `~/.config/magpie/`（600），**不进 `plugin-auth.json`**；
  打印只输出状态与业务码，绝不打印 cookie / key / 口令的值。
